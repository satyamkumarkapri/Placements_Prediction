Why We Need Encoding

Machine learning algorithms operate strictly on numbers. They cannot understand categorical text data like "Tier1" or "Networking". Categorical encoding transforms these strings into meaningful numerical representations that models can process.

The Three Encoders

We evaluate three primary methods to encode categorical features.

Encoding Method How It Works Pros / Cons Best Used For
One-Hot Encoder Creates a new binary (0 or 1) column for every unique category. Networking -> [1, 0, 0, 0] Can cause dimensionality explosion if there are too many categories (Curse of Dimensionality). Unordered (Nominal) data with low cardinality (e.g., Specialisation, Gender, Country).
Ordinal Encoder Assigns an ordered integer to each category based on an explicit mapping. Tier3 -> 0, Tier2 -> 1, Tier1 -> 2 Preserves the mathematical relationship and rank between categories. Ordered (Ordinal) data (e.g., CollegeTier, Satisfaction Rating, Education Level).
Target Encoder Replaces a category with the mean of the target variable for that category. Networking -> 0.72 (72% placement rate) Highly predictive, but prone to data leakage/overfitting without cross-validation. High-cardinality nominal data (e.g., ZIP Code, City, Job Title).

Pipeline Implementation

How we applied this in train_model.py:

  • CollegeTier (OrdinalEncoder): Since Tier 1 is strictly better than Tier 2, and Tier 2 is strictly better than Tier 3, we map them as [Tier3, Tier2, Tier1] -> [0, 1, 2].
  • Specialisation (OneHotEncoder): Since there is no inherent ranking between Networking, AI, and DataScience, we use One-Hot encoding to treat them equally without implying a false order.

The Target Leakage Trap

Why Target Encoding is risky:

Because Target Encoding uses the target variable (PlacementStatus) to calculate the mean, applying it to the whole dataset before splitting into Train/Test will cause severe data leakage. Scikit-learn's TargetEncoder uses internal cross-validation during fit_transform() to naturally smooth out this leakage and prevent overfitting!
